# API reference

Generated by `treeyard api-doc` from the operation table in `src/rpc.rs`. Do not edit by hand: `tests/docs.rs` fails when this file and the table differ.

Every operation has three transports. All three take the same JSON parameters and give the same JSON reply.

| Transport | Call |
|---|---|
| HTTP | `POST /api/<op>` with a JSON object body; reply `200` with JSON, or an error status with `{"error": "..."}` |
| MCP (stdio) | `tools/call` with `name` = `<op>` and `arguments` = the parameters (`treeyard mcp`) |
| CLI | `treeyard call <op> '<json>'` (server from `TREEYARD_URL`, token from `TREEYARD_TOKEN`) |

Error statuses: `400` invalid JSON, `401` no valid token, `403` the token has no right, `404` an operation name that is not lowercase letters and `_`, `422` the operation failed (also an unknown operation), `503` the server is busy (retry). The protocol is described in [spec/rpc.md](spec/rpc.md).

Other routes: `GET /health` answers `ok`; `GET /api/events` is the server-sent event stream of [`events`](#events); `POST /api/tools` returns this table as JSON (the MCP `tools/list` reply, also `treeyard api-doc --json`); `/git` serves git smart HTTP ([git-http.md](git-http.md)).

A revision (`at`, `from`, `to`, `base`, `good`, `bad`, `changeset`) is `main`, a change id `ch_...`, a changeset id or a unique prefix of one, or a 40-hex git commit id.

### bisect

Find the first bad changeset between good and bad (default main) on the first-parent history: the server runs a test command from treeyard.toml on temporary checkouts. Then call revert on it if you want it gone.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `bad` | string | no | main (default), a change id ch_..., a changeset id or prefix, or a git commit id |
| `command` | string | no | name of a command in [bisect.commands]; default [bisect] test or landing.test |
| `good` | string | yes | main (default), a change id ch_..., a changeset id or prefix, or a git commit id |
| `verify` | boolean | no | test good and bad first (default true) |


## Changes

### open_change

Start a change on top of main (no branch). Declare the paths and symbols you plan to touch: the reply lists open changes that overlap them, with advice. Edit with apply, then land.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `agent` | string | no |  |
| `base` | string | no | main (default) or another revision; a change id ch_... stacks on that change, which then lands first |
| `group` | string | no | best-of-N: changes that try the same task share a group name; land_one_of lands one and abandons the rest |
| `intent` | string | yes | what you are about to do, in one line |
| `model` | string | no |  |
| `paths` | array of string | no | path globs you will edit, e.g. src/parser/** or Cargo.toml |
| `session` | string | no |  |
| `symbols` | array of string | no | function, type or class names you will change; name or path#name |

```sh
treeyard call open_change '{"intent": "fix a typo"}'
```

### declare

Replace the paths and symbols a change plans to touch; returns overlaps with other open changes.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `change` | string | yes | change id, ch_... |
| `paths` | array of string | no | path globs you will edit, e.g. src/parser/** or Cargo.toml |
| `symbols` | array of string | no |  |

```sh
treeyard call declare '{"change": "ch_..."}'
```

### apply

Edit files in a change: per edit give content, content_b64, delete:true, replace:{old,new,all?}, and optionally executable. Returns the change, other open changes touching the same paths, and live collisions (trial merge: conflict or overlap, with hunk ranges).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `change` | string | yes | change id, ch_... |
| `edits` | array of object (`content`, `content_b64`, `delete`, `executable`, `path`, `replace`, `symlink`) | yes |  |
| `message` | string | no | commit message; defaults to the intent |
| `seen` | string | no | the revision your whole-file contents are based on (e.g. the head you read); the server merges if the change moved since |

```sh
treeyard call apply '{"change": "ch_...", "edits": [{"path": "README.md", "replace": {"old": "teh", "new": "the"}}]}'
```

### resolve

Settle a conflicted path by taking one side (or write the path with apply).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `change` | string | yes | change id, ch_... |
| `path` | string | yes |  |
| `take` | one of `ours`, `theirs`, `base`, `delete` | yes |  |

```sh
treeyard call resolve '{"change": "ch_...", "path": "README.md", "take": "ours"}'
```

| Parameter | Type | Required | Description |

## Checkpoints and attachments

### checkpoint

Mark the current head of an open change as the next checkpoint (one per agent turn is a good rhythm). Returns its id and number; a head that is already the newest checkpoint is not marked again (repeated = true).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `change` | string | yes | change id, ch_... |
| `label` | string | no | a short note, e.g. the turn or the step |

```sh
treeyard call checkpoint '{"change": "ch_..."}'
```

### checkpoints

The checkpoints of a change, oldest first: id, number, changeset, label, time, and the paths that changed since the previous checkpoint.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `change` | string | yes | change id, ch_... |

```sh
treeyard call checkpoints '{"change": "ch_..."}'
```

### restore_change

Undo inside an open change: make a new head whose tree equals an earlier state. History is kept: the head before the restore becomes a checkpoint (its number is in undo), so a restore can be undone. If the change was rebased since, that state's edits are merged onto the current base.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `change` | string | yes | change id, ch_... |
| `to` | string or integer | yes | checkpoint id cp_..., checkpoint number (0 = the base, no edits), or a changeset id of this change |

```sh
treeyard call restore_change '{"change": "ch_...", "to": 2}'
```

### attach

Store a transcript, summary or note with an open change (up to 256 KiB each), so a later agent can read why the code changed. Lines that look like secrets (sk-, ghp_, github_pat_, AKIA, xox tokens, key = value secrets, private key blocks) are dropped; the reply says how many. On land it becomes a git note on the landed commit (refs/notes/treeyard).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `change` | string | yes | change id, ch_... |
| `kind` | one of `transcript`, `summary`, `note` | yes |  |
| `text` | string | yes |  |

```sh
treeyard call attach '{"change": "ch_...", "kind": "summary", "text": "why: the parser dropped a trailing comma"}'
```

### attachments

The attachments of a change, oldest first, and for a landed change the git note that holds them (git notes --ref=treeyard show <commit>).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `change` | string | yes | change id, ch_... |

```sh
treeyard call attachments '{"change": "ch_..."}'
```

## Shared directories

### assign

Agents that share one directory: send the directory's changed files (relative to the share base); each file's diff splits into hunks with stable ids, and each hunk gets one owner among the share's changes: a claim, then a declared symbol or path, then its earlier owner. Reply: hunks per change (depends_on = it builds on another change's hunk and is held) and unassigned hunks.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `base` | string | no | base revision of the share (default: main when the share is new); a new base moves the share, after every open change was rebased onto it |
| `changes` | array of string | no | the open changes of the agents in this directory (default: as before) |
| `files` | array of object (`content`, `delete`, `path`) | no | every file that differs from the base; others count as equal to it |
| `share` | string | yes | share name, e.g. the directory path |

```sh
treeyard call assign '{"share": "..."}'
```

### claim

Give hunks (ids from assign) of a shared directory to a change, before any intent or earlier owner. A claim follows the hunk while it grows.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `change` | string | yes | change id, ch_... |
| `hunks` | array of string | yes |  |
| `share` | string | no | default: the share that lists the change |

```sh
treeyard call claim '{"change": "ch_...", "hunks": "..."}'
```

### apply_assigned

Write a change's own hunks of a shared directory into the change: base plus its ready hunks, merged 3-way onto the head when it was rebased. Hunks that depend on another change come back in held, unapplied.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `change` | string | yes | change id, ch_... |
| `share` | string | no | default: the share that lists the change |

```sh
treeyard call apply_assigned '{"change": "ch_..."}'
```
