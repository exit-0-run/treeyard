# API reference

Generated by `rootstock api-doc` from the operation table in `src/rpc.rs`. Do not edit by hand: `tests/docs.rs` fails when this file and the table differ.

Every operation has three transports. All three take the same JSON parameters and give the same JSON reply.

| Transport | Call |
|---|---|
| HTTP | `POST /api/<op>` with a JSON object body; reply `200` with JSON, or an error status with `{"error": "..."}` |
| MCP (stdio) | `tools/call` with `name` = `<op>` and `arguments` = the parameters (`rootstock mcp`) |
| CLI | `rootstock call <op> '<json>'` (server from `ROOTSTOCK_URL`, token from `ROOTSTOCK_TOKEN`) |

Error statuses: `400` invalid JSON, `401` no valid token, `403` the token has no right, `404` an operation name that is not lowercase letters and `_`, `422` the operation failed (also an unknown operation), `503` the server is busy (retry). The protocol is described in [spec/rpc.md](spec/rpc.md).

Other routes: `GET /health` answers `ok`; `GET /api/events` is the server-sent event stream of [`events`](#events); `POST /api/tools` returns this table as JSON (the MCP `tools/list` reply, also `rootstock api-doc --json`); `/git` serves git smart HTTP ([git-http.md](git-http.md)).

A revision (`at`, `from`, `to`, `base`, `good`, `bad`, `changeset`) is `main`, a change id `ch_...`, a changeset id or a unique prefix of one, or a 40-hex git commit id.

No parameters.

## History and code intelligence

### log

History of main (or of at), newest first, from the changed-path index. Filters: path (file or directory), paths (globs: only changesets touching a match), agent, since/until (unix seconds).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `agent` | string | no |  |
| `at` | string | no | main (default), a change id ch_..., a changeset id or prefix, or a git commit id |
| `limit` | integer | no |  |
| `path` | string | no |  |
| `paths` | array of string | no |  |

rootstock call log '{}'

### bisect

Find the first bad changeset between good and bad (default main) on the first-parent history: the server runs a test command from rootstock.toml on temporary checkouts. Then call revert on it if you want it gone.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `bad` | string | no | main (default), a change id ch_..., a changeset id or prefix, or a git commit id |
| `command` | string | no | name of a command in [bisect.commands]; default [bisect] test or landing.test |
| `good` | string | yes | main (default), a change id ch_..., a changeset id or prefix, or a git commit id |
| `verify` | boolean | no | test good and bad first (default true) |

```sh
rootstock call bisect '{"good": "<changeset id>"}'
```

## Changes

### open_change

Start a change on top of main (no branch). Declare the paths and symbols you plan to touch: the reply lists open changes that overlap them, with advice. Edit with apply, then land.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `agent` | string | no |  |
| `base` | string | no | main (default) or another revision; a change id ch_... stacks on that change, which then lands first |
| `intent` | string | yes | what you are about to do, in one line |
| `model` | string | no |  |
| `paths` | array of string | no | path globs you will edit, e.g. src/parser/** or Cargo.toml |
| `session` | string | no |  |
| `symbols` | array of string | no | function, type or class names you will change; name or path#name |

```sh
rootstock call open_change '{"intent": "fix a typo"}'
```

### declare

Replace the paths and symbols a change plans to touch; returns overlaps with other open changes.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `change` | string | yes | change id, ch_... |
| `paths` | array of string | no | path globs you will edit, e.g. src/parser/** or Cargo.toml |
| `symbols` | array of string | no |  |

```sh
rootstock call declare '{"change": "ch_..."}'
```

### apply

Edit files in a change: per edit give content, content_b64, delete:true, replace:{old,new,all?}, and optionally executable. Returns the change, other open changes touching the same paths, and live collisions (trial merge: conflict or overlap, with hunk ranges).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `change` | string | yes | change id, ch_... |
| `edits` | array of object (`content`, `content_b64`, `delete`, `executable`, `path`, `replace`, `symlink`) | yes |  |
| `message` | string | no | commit message; defaults to the intent |
| `seen` | string | no | the revision your whole-file contents are based on (e.g. the head you read); the server merges if the change moved since |

```sh
rootstock call apply '{"change": "ch_...", "edits": [{"path": "README.md", "replace": {"old": "teh", "new": "the"}}]}'
```

### resolve

Settle a conflicted path by taking one side (or write the path with apply).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `change` | string | yes | change id, ch_... |
| `path` | string | yes |  |
| `take` | one of `ours`, `theirs`, `base`, `delete` | yes |  |

```sh
rootstock call resolve '{"change": "ch_...", "path": "README.md", "take": "ours"}'
```

### rebase

Rebase a change onto current main on the server. Conflicts come back as typed tasks.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `change` | string | yes | change id, ch_... |

```sh
rootstock call rebase '{"change": "ch_..."}'
```

### land

Land a change on main: rebases on the server if main moved. Returns status landed (with the git commit), queued (landing mode queue), already_on_main (main had every edit; a review task is opened), waiting (stacked on a change that has not landed), or conflict (with tasks). Also lists merge drivers used and review tasks.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `change` | string | yes | change id, ch_... |

```sh
rootstock call land '{"change": "ch_..."}'
```

## Coordination

### events

Coordination events after seq `since`: opened, intent_overlap, collision, conflict, rebased, landed, review, queued, rejected, test_failed, reverted. Long-poll with wait_ms (max 30000). Pass the reply's next as since. Also GET /api/events (server-sent events).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `agent` | string | no |  |
| `change` | string | no | change id, ch_... |
| `kinds` | array of string | no |  |
| `limit` | integer | no |  |
| `since` | integer | no |  |
| `wait_ms` | integer | no |  |

```sh
rootstock call events '{}'
```

| `state` | one of `open`, `done`, `dismissed`, `all` | no |  |

rootstock call reviews '{}'

### queue

### test_main
