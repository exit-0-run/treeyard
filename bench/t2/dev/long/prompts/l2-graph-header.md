# Line formats: a header line with the graph type

Files in the edge list, adjacency list and multiline adjacency list formats (`networkx/readwrite/edgelist.py`, `networkx/readwrite/adjlist.py` and `networkx/readwrite/multiline_adjlist.py`) do not say whether the graph is directed or a multigraph, or what its name is, so the reader has to know and pass `create_using`. Add an optional header line.

- The header line is `<comments> networkx-graph: directed=<True|False> multigraph=<True|False>`, with the comments string of the call: with the default `"#"` it is `# networkx-graph: directed=True multigraph=False` for a `DiGraph`. A graph with a name (`G.name` not empty) gets ` name=<json>` at the end, where `<json>` is `json.dumps(str(G.name))`: `# networkx-graph: directed=True multigraph=False name="big \"roads\""`.
- `generate_edgelist`, `generate_adjlist` and `generate_multiline_adjlist` take `header=False, comments="#"`; with `header=True` they yield the header line first, then the lines they yield today.
- `write_edgelist`, `write_weighted_edgelist`, `write_adjlist` and `write_multiline_adjlist` take `header=False`. With `header=True` the first line they write is the header line, with the `comments` argument of the call. The comment lines that the adjacency list writers write today come after it. Without `header=True` all output is as today.
- `parse_edgelist`, `parse_adjlist`, `parse_multiline_adjlist` and the `read_*` functions: when `create_using` is `None` and a header line comes before the first data line, the graph is a `Graph`, `DiGraph`, `MultiGraph` or `MultiDiGraph` as the header says, and a name in the header is its `G.graph["name"]`. A header line is a line whose text, stripped, is the comments string followed by the words `networkx-graph:`, `directed=<True|False>` and `multigraph=<True|False>`, and optionally, after one more space, `name=` and a JSON string (the rest of the line). A line that does not match exactly (another fourth word, a name that is not valid JSON or not a JSON string) is a comment as before, and so is a header line after the first data line. Other comment lines and blank lines may come before the header. With `create_using` given the header changes nothing, and `comments=None` (edge list) means no header.
- In `networkx/readwrite/edgelist.py`, listed in its `__all__` (so they are `nx.parse_graph_header` and `nx.read_graph_header`):
  - `parse_graph_header(lines, comments="#")` returns `{"directed": bool, "multigraph": bool, "name": str or None}` of the header line when one comes before the first data line, else `None`. It stops at the first data line: it does not take further lines from `lines`.
  - `read_graph_header(path, comments="#", encoding="utf-8")` does the same for a file (a path, a file name or an open binary file, opened as the `read_*` functions open it), and reads no line after the first data line.

Document the parameters in each function and the header in the module docstring of each of the three modules.
